# 거래 정합성 개선 상세

## 원자성과 재시도

모든 HTTP 거래는 IdempotencyService.execute를 통과합니다. 키 선점, 조건부 잔액 갱신, 원장 INSERT, 응답 직렬화와 COMPLETED 변경을 하나의 MySQL 트랜잭션으로 묶습니다. TransactionTemplate은 REQUIRES_NEW / REPEATABLE_READ이며 최대 5회의 재시도 경계는 커밋까지 포함합니다.

실패한 트랜잭션 안에서 다시 조회하거나 재시도하지 않습니다. 중복 주장 충돌은 롤백 후 새로운 스냅샷에서 재생합니다. MySQL 오류 1062, SQLSTATE 23000과 정확한 uk_idempotency_actor_key 제약 이름이 일치할 때만 이 경로를 허용합니다. 다른 무결성 오류를 중복 요청으로 숨기지 않습니다.

TransactionService의 내부 호출용 오버로드는 유지합니다. HTTP 이외의 호출자는 멱등성·재시도 경계를 책임져야 합니다. HTTP 거래의 감사 필드는 항상 채우며, 과거 데이터와 내부 테스트 초기화 이력은 키 참조가 없을 수 있습니다.

## 요청 계약

- 키는 사용자별로 구분하고 ASCII `[A-Za-z0-9._:-]{1,100}`만 허용합니다.
- 작업과 순서가 있는 계좌 목록·두 자리로 정규화한 금액을 SHA-256 지문으로 묶습니다. 같은 키의 요청 내용이 바뀌면 C017입니다.
- 금액은 양수, 소수 두 자리 이하, DECIMAL(19,2) 범위입니다. 서비스에서도 검사하여 HTTP 검증 우회를 막습니다.
- 입금 상한은 BigDecimal 매개변수를 바인딩한 조건부 UPDATE로 검사합니다. JPQL의 큰 숫자 리터럴 형식으로 생길 수 있는 정밀도 문제를 피합니다.
- 모의 입금은 기본 비활성화입니다. prod에서는 항상 차단하고 실제 외부 입금 확인을 구현했다고 주장하지 않습니다.
- 응답의 transactionId / actorId / idempotencyId를 통해 원장·수행자·키 행을 연결합니다. 로그는 afterCommit에 ID와 작업만 기록합니다.

## 마이그레이션과 보존

새 유일 제약은 `uk_idempotency_actor_key(actor_id,idempotency_key)`입니다. 주 키 컬럼은 utf8mb4_0900_bin으로 대소문자와 후행 공백을 구분합니다. 과거 NO PAD 규칙에서 별개였던 key와 key<공백>을 합치지 않습니다.

legacy_key는 기존 컬럼의 정확한 문자셋·collation을 보존합니다. 소유자를 복원할 수 없는 과거 행은 actor 0 / LEGACY / 64자리 0 지문으로 격리합니다. 원래 비교 규칙상 동등한 키도 거절하며 과거 응답을 새 사용자에게 반환하지 않습니다. 오래된 재시도의 중복 실행을 막기 위해 키를 단순 TTL로 삭제하지 않습니다.

거래 이력에는 nullable actor_id, idempotency_key_id FK와 송·수신 계좌/ID 인덱스를 추가합니다. 과거 행의 수행자를 임의로 추측하여 채우지 않습니다. 자세한 이전 절차는 OPERATIONS_RUNBOOK을 따릅니다.

## 이력 탐색

기존 Page 응답은 유지하고 id DESC 및 size 1~100을 고정합니다. 새 beforeId 커서는 새 높은 ID 삽입으로 다음 페이지가 밀리는 현상을 피합니다. 늦게 커밋한 거래까지 포함하는 불변 스냅샷이나 회계 마감 내보내기는 별도 요구사항입니다.

## 검증 근거

수정 전 거래 회귀 테스트 12개 중 11개, 추가 직렬화/감사 로그 테스트 2개 모두 실패했습니다. legacy 별칭 테스트도 수정 전 실패했습니다. 최대 잔액 검증 중 JPQL 리터럴 형식 문제가 발견되어 BigDecimal 바인딩으로 고쳤습니다.

분야별 실행은 55개 전체 통과, 마지막 legacy/수취인 보완 후 관련 23개 통과였습니다. 최종 통합본은 다른 영역을 포함해 Java 134개 전체 통과했습니다. 이 수치는 중복 합산하지 않습니다.

실제 MySQL 트리거로 완료 UPDATE·원장 INSERT·일시적/지속적 충돌을 주입했습니다. 50개 동일 키 Future를 모두 기다리고 같은 거래 ID 50개, 원장 1행, 키 1행을 확인했습니다. 양방향 이체는 100건 성공, 이력 100건과 양쪽 잔액을 확인합니다.

장애 주입용 MyISAM 카운터는 롤백을 넘어 테스트 시도 횟수를 기록하기 위한 일회용 테스트 도구입니다. 운영 업무 테이블은 InnoDB입니다. 검증 시간을 처리량/SLA 수치로 해석하지 않습니다.
