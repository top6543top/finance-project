# 금융 서비스 코드 개선 계획

기준: 2026-09-29 리뷰 R01-R19, 커밋 7d6f766. 사용자가 전체 수정과 문서화·재검토를 요청한 범위를 실행한다.

## 설계와 완료 조건

단일 MySQL과 기존 Spring 계층 구조를 유지한다. 금액은 소수 두 자리이며 암묵적 반올림을 금지한다. 모의 입금은 명시적으로 허용한 학습 환경에서만 가능하다. 실입금 연동을 임의로 만들지 않는다. 원본은 검증 전까지 보존하고 격리 복사본에서 변경한 후 파일 해시를 대조하여 반영한다.

- [x] 거래 정합성(R01-R04, R10, R17-R19): 키·주체·작업·요청 지문을 묶고 키 완료와 거래를 같은 트랜잭션에 커밋한다. 실패한 트랜잭션 밖에서 재시도/재생한다. 금액·잔액 상한, 입력 키 검증, 거래 식별자와 수행자 기록을 추가한다. 실패 재현 → 수정 → MySQL 재검증 순서로 진행한다.
- [x] 보안(R05-R06): 예외 로그에 거절 값을 출력하지 않는다. 신뢰되지 않은 전달 헤더를 사용하지 않으며 로그인 제한 장애는 차단한다. JWT와 회원 입력 경계를 점검한다. 민감값 로그와 헤더 위조 회귀 테스트로 확인한다.
- [x] 운영 대사(R11-R13): 현재 잔액 점검과 영업일 마감을 구분한다. 불일치와 실행 결과를 보존하고 지표/경보를 제공한다. 누락 실행 감지와 중단 실행의 안전한 복구 절차를 제공한다. MySQL 배치 테스트에서 결과 저장과 복구 경계를 확인한다.
- [x] 배포와 DB(R07-R09, R14-R16): Redis와 TLS 설정을 필수 주입한다. 운영 DDL 자동 변경을 제거하고 버전 마이그레이션으로 빈 DB 설치 및 업그레이드를 검증한다. 동일 SHA 테스트 성공 후 이미지를 생성하고 직렬 배포한다. 실제 앱 포트의 readiness/liveness를 검사한다.
- [x] 통합 및 문서: 기존·새 테스트 전체를 실행하고 수정 차이를 다시 리뷰한다. 각 R 항목을 수정/환경 검증 필요로 구분해 Markdown과 PDF로 docs에 저장한다. 운영 인프라 접속, 실제 자금 이동, 배포는 수행하지 않는다.

## 작업 단위

1. `domain/idempotency`, `domain/transaction`, `domain/account`: 금액 정책 및 원자적 요청 처리. 서비스 프록시·unique 충돌·DB 완료 기록 실패·동시 20개 이상 요청·타 사용자 키 재사용·변경된 요청 거절을 검증한다.
2. `common/exception`, `common/ratelimit`, `common/security`, `domain/member`: 비밀값 누출 방지와 인증/입력 경계. 기존 코드에서 실패하는 기대를 먼저 실행한다.
3. `domain/reconciliation`: 실행 의미, 결과 저장, 누락/중단 대응. 실제 DB 대사 결과와 재실행의 중복 방지 조건을 검증한다.
4. `build.gradle`, `src/main/resources`, `.github/workflows`, `k8s`, `scripts`: 마이그레이션과 안전한 릴리스. 신규 및 기존 스키마 경로를 테스트 컨테이너에서 실행한다.
5. 모든 변경의 전체 테스트, 별도 최종 리뷰, API 예제/운영 절차/개선 결과 문서와 PDF 검수.

## 반영 원칙

보존 중인 로컬 비밀값 파일은 복사하거나 수정하지 않는다. 기존 데이터를 삭제하지 않는다. 마이그레이션은 운영 DB에 실행하지 않으며 기존 중복키 데이터 보존과 이전 버전 공존 한계를 명시한다. 실제 인프라의 TLS 인증서·계정 권한·백업 복원·알림 전달은 코드만으로 확인할 수 없으므로 남은 운영 승인 조건으로 제시한다.
